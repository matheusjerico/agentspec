## Key Decisions

### Decision 1: One `traceability` block feeds both phase contracts `[ASSUMED 0.90]`
CLI reads it once; design side takes vocabulary + design-rule severities, build side takes coverage severities. Absent block → all TX/BR-matrix rules off (backward compatible, established pattern).

### Decision 2: `_section_exact("traceability_matrix")` in BOTH parsers `[ASSUMED 0.95]`
Increment 5's decoy lesson applied from birth — no prefix scanning for a template-fixed heading. Design rows: 6 cells (`#`, REQ, Priority, Tasks, Tests, Type); build rows: 8 (+ Result, Review). Parsers guard on cell count; placeholder brace-guard mirrored from Increment 5.

### Decision 3: Orphan checks are lenient by token grammar `[ASSUMED 0.85]`
`TX.orphan_reference` (WARN) fires only for: matrix Tasks cells citing ids absent from a PRESENT v2 manifest, and manifest `requirements` refs matching `^REQ-` that are absent from the matrix. Legacy refs (`MUST-n`, `SC-n`) never flag — pre-REQ-ID manifests stay silent (DEFINE A-002).

### Decision 4: `exception:` prefix in the Tests cell is the contractual-exception grammar `[ASSUMED 0.85]`
Mirrors Increment 4's sanctioned grammar precedent: a MUST row whose Tests cell starts with `exception:` (with citation) is exempt from `BR.must_uncovered` — recorded, auditable, deterministic.

```python
# design rows: | # | REQ | Priority | Tasks | Tests | Type |            -> 6 cells

# _section_exact(artifact, "traceability_matrix"); _NUMBERED_ROW per row;
# brace-guard on REQ and Priority cells (placeholder rows skipped).
```

### Pattern 2: MUST-coverage check (build side)

```python
if priority == "must":
    tests_cell = cells[4]
    if tests_cell.lower().startswith("exception:"):
        continue                       # contractual exception, recorded
    if not tests_cell or tests_cell == "-" or "pass" not in cells[6].lower():
        findings.append(...)           # BR.must_uncovered naming the REQ
```

### Pattern 3: Orphan grammar guard

```python
_REQ_TOKEN = re.compile(r"^REQ-\d+$")
# manifest requirement refs: flag only tokens matching _REQ_TOKEN missing from the matrix
```

## Data Flow

```text
1. Define assigns REQ IDs in the Goals table
2. Design generates the matrix (REQ → tasks → tests → type); frontend policy
   adds e2e/browser rows when a web UI exists; TX rules validate structure
3. Build fills Result (from verification runs) + Review (from task verdicts);
   BR rules validate MUST coverage; absence WARNs only at high/critical
4. Ship confirms coverage from the filled matrix; PR description reuses it
   (automation in Increment 8)
```
