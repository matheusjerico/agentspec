## Summary

The Build Quality Gates promises (Review Verdict, Gate R, TDD Evidence) are now executable contracts instead of documentary ones. A new `BuildReportContract` in spec-linter validates every BUILD_REPORT deterministically — section presence plus semantic rules for verdict values (dirty/missing fail-closed), unresolved Critical/Important findings, fix-round budgets, TDD evidence, task completeness, and schema versioning — parameterized entirely from `WORKFLOW_CONTRACTS.yaml` (v3.8.0, Build binding flipped `specified target` → `wired`). The gate is wired into three consumers: sdd-build Step 6.5, sdd-ship's `build_report_contract_gate_pass` checklist item, and Autopilot's Gate L/Gate S with `--legacy-mode fail`. Plugin parity is now proven after every package by `build-plugin.sh` Step 5e. This is Increment 1 / PR 1 of the incremental-improvements plan — the evidence foundation Increments 2–9 build on.

## Lessons Learned

### Process

- Budget review rounds for gate code deliberately: the adversarial review caught three successive weakenings of the same fail-closed rule (word match → prefix match → template-shaped pattern) across 2 fix rounds — the 2-round budget was exactly consumed. Gate/validator code should be assumed to need its full review budget.
- Dogfood on day one: running the new gate on its own build report immediately caught a real authoring hazard (a raw `|` inside a code span splits Markdown table cells and silently corrupts the parsed resolution). Shipping a gate without validating a real artifact would have hidden this.

### Technical

- When two checks interpret the same document structure (section presence vs. section scoping), they must share one parser/vocabulary — the round-2 Critical existed precisely because presence used any-level headings while scoping used `##`-only. Now both bind on `##`.
- Parity comparison must normalize BOTH sides: canonical files can legitimately contain plugin-form literals (`${CLAUDE_PLUGIN_ROOT}/...` in explanatory comments), so one-sided normalization manufactures false divergence.
- Quote YAML enum values that collide with YAML 1.1 booleans — `off` unquoted parses as `False` under PyYAML; `tdd_mode_values: ["off", ...]` avoided a silent contract corruption.
- A pre-build test run cannot assert parity of the package it is about to replace — split behavior tests (pre-package) from parity (post-package) or the build deadlocks on its own gate.

### Communication

- The source plan pre-decided the scope fork (§23 "start with PR 1", §16.4 per-increment dogfooding), which let Define scope to Increment 1 without a blocking human question — plans that encode their own sequencing keep autonomous phases unblocked.
- Recording the accepted residual (interposed-heading scan truncation) in the Build Report, with rationale, converted a potential silent gap into a reviewable scope boundary — the reviewer explicitly endorsed it as "disclosed rather than swept under the rug".

### Tools & Libraries

- The delegation fan-out (python-developer, test-generator ×3, shell-script-specialist, code-reviewer ×3) with tight per-file prompts kept 13 files consistent; the parity-test agent even correctly reported its own expected failures instead of weakening assertions when told not to.
- `rtk proxy python3 -m pytest` is required in this environment — the rtk PreToolUse hook rewrites bare pytest invocations to a binary not on PATH.
