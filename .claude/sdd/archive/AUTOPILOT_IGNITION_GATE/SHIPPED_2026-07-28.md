## Summary

Autopilot no longer starts autonomous runs on under-specified intents. A mandatory, human-answered interview (interactive Brainstorm + Define) now runs before anything autonomous exists, and the run ignites only when the DEFINE **re-scores** 15/15 at Gate I — the recorded score is never trusted. Post-ignition, a new Gate D ensures no Design decision below 0.80 confidence is ever assumed: interactive runs ask the user (un-capped, ledger-recorded); headless runs abort with a structured Pending Decision block that an interactive resume re-asks 1:1. The headless runner's contract changed accordingly: it accepts only a pre-validated DEFINE path, and a raw intent is a preflight usage error. The value delivered: the failure mode where autopilot machine-filled requirement gaps with `[ASSUMED]` defaults and implemented the wrong thing is structurally eliminated.

## What Was Built

### Components

| Component | Description |
|-----------|-------------|
| Gate I (Ignition) | Replaces Gate 0: re-reads the DEFINE from disk and re-scores it (5 elements × 0–3); only a recomputed 15/15 opens the run; below → `❌ Aborted (I)` with a recomputed gap report and discrepancy note |
| Pre-ignition interview | `/auto "<intent>"` sequences supervised `sdd-brainstorm` + `sdd-define` with native interactive conduct until 15/15 — zero `[ASSUMED]` markers before ignition; abandonment leaves no run |
| Three-form `/auto` surface | Intent (interview) · DEFINE path (straight to Gate I) · FEATURE_NAME (resume) |
| Gate D (Decision) | Design decisions < 0.80 confidence: interactive → `AskUserQuestion`, un-capped, ANSWERED ledger rows; headless → `❌ Aborted (D)` + structured Pending Decision block; resume re-asks 1:1 |

| Run report extensions | DEFINE-input metadata, I/D ledger legend + ANSWERED outcome, Pending Decision section, Human Interactions count, Gate-I gap report |

## Lessons Learned

### Process

- The feature was mostly **deletion, not construction**: the mandatory interview already existed as the phase skills' native interactive conduct — autopilot's overrides were suppressing it. Before building new machinery for a "new" behavior, check whether an existing capability is merely being overridden by policy.
- Dogfooding the gate paid off immediately: this feature's own DEFINE reached 15/15 by answering its 3 open questions in-session (~3 minutes) — the cost the ignition gate imposes is minutes of questions versus a full wrong-direction run.

### Technical

- Descriptive summaries of policy in a second file are a drift liability: `WORKFLOW_CONTRACTS.yaml`'s `autopilot:` block silently recorded now-false facts (12/15 gate, unconditional invariant) and the DESIGN's "does not change" table missed it. Either keep such blocks strictly contract-grade or generate them from the source of truth.
- Preflight check *ordering* is part of a script's testable contract: placing `validate_define_argument` after the repo-root `cd` changed which check fires first, which broke the assumption behind one migrated test. When reordering preflights, re-verify which failure each existing test actually asserts.

### Communication

- The one-question-at-a-time discovery surfaced a user preference that **inverted the recommended design**: post-ignition autonomy was recommended as total, and the user chose Gate D pauses instead — reshaping the core invariant. Presenting a recommendation while genuinely allowing the override produced a materially different (and better-fitting) architecture.

### Tools & Libraries

- Delegation prompts with mechanically checkable acceptance criteria ("message must contain 'DEFINE' and '/auto'", "shellcheck must pass") let specialists self-verify and made the orchestrator's independent re-verification nearly free.
- The existing stub-based pytest harness (fake `claude` on PATH recording argv) absorbed a full input-contract change with zero new infrastructure — a strong argument for that test design.
