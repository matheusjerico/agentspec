## Summary

The three fail-open paths a Codex cross-model review found in the nine-increment program are closed. Configuration is now fail-closed: an opt-in block that is present but not a mapping (explicit null, string, list — the indentation-drift scenario) is an exit-2 operational error on both phases, never a silent disarm, and the design router can no longer silently downgrade to the plain contract. Row parsing is fail-closed: truncated or placeholder-bearing Traceability Matrix and Task Reviews rows are `BR./TX.matrix_row_malformed` / `BR.task_review_row_malformed` FAILs instead of silent drops — a hidden MUST row or a truncation-hidden dirty verdict can no longer produce a PASS. Built TDD RED-first (41 verified failures before implementation); the reviewer live-reproduced the Codex scenarios against main vs the branch. No vocabulary changes; absent blocks keep byte-compatible dormant behavior.

## Lessons Learned

### Process

- Cross-model review pays for itself: three real fail-open paths survived nine rounds of same-model adversarial review — a different model attacked the *tolerances* (config drift, truncation) rather than the rules, and found what pattern-familiarity had normalized.
- "Disclosed residual" comments are a debt register: every one of the three findings sat next to a comment describing itself. A disclosed trade-off should carry an owner and an expiry, or it becomes permanent.

### Technical

- Fail-closed has two distinct surfaces: input validation (rows) and configuration validation (wiring). Hardening one without the other leaves the control bypassable — the review exploited both sides of the same class.
- `key in data` vs `data.get(key)`: distinguishing explicit-null from absent is the whole game for opt-in config — `get()` erases the difference the guard needs.
