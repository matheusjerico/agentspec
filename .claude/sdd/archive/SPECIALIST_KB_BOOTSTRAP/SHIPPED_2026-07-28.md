## Summary

Generated specialist agents are no longer born ungrounded: when the provisioning flow (SPECIALIST_AUTOPROVISION, shipped earlier the same day) creates an agent for a domain with no KB, the agent now declares `kb_domains: [domain]` and the file manifest gains a KB-creation task — executed by `kb-architect` on its own frontmatter model (Sonnet, never the main loop's) — dependency-ordered before the specialist's first delegated task. The generated KB is light but disciplined: `genai`-shaped, structural claims (versions, API signatures, config defaults, code examples) must cite official docs fetched during the pass, and every file opens with a provenance header that doubles as the machine sensor for the second half of the feature: any later run that delegates to an agent whose KB is still marked auto-generated appends a `--validated` upgrade (`kb-build`) as its final best-effort task, capped at one promotion per run — drip promotion that converges the fleet to validated grounding without any single run paying a cost spike. Failure anywhere degrades loudly to the previous shipped behavior (`kb_domains: []` + WARN); no run ever aborts because of a KB.

## Lessons Learned

### Process

- The second feature validated the first one's architecture: the entire KB bootstrap fit in 2 logic files with zero new gates, zero new components, and zero changes to `sdd-design` — because the parent left real extension points (a sub-flow step to extend, dependency-ordered manifest tasks, Gate B governing arbitrary tasks). When the natural extension lands entirely in existing hooks, the original decomposition was right.
- A YAGNI cut can come back *better*: auto-upgrade was cut at the parent's brainstorm, and the user pulled it back with a sharper trigger (reuse, not creation) and bounded timing (final best-effort task). Recording cuts with "Can Add Later? Yes" made the return a scoped decision instead of scope creep.

### Technical

- Bound best-effort tail work explicitly: "upgrade every unvalidated KB touched" reads as more complete but makes worst-case run cost unbounded. The 1-per-run drip promotion trades immediate completeness for predictable cost with guaranteed convergence — rate-limiting applied to self-improvement.
- Reuse an existing artifact as the sensor before adding metadata: the provenance header (extending the `genai` house style) doubles as human warning and machine sensor, avoiding an `_index.yaml` schema change whose consumers span every phase's KB discovery step.
- Concentrate validation where hallucination causes concrete damage: requiring citations only for structural claims (versions, signatures, defaults, code) keeps the single-pass cost profile while making verification checkable — an uncited structural claim fails the task, not a vibe check.

### Communication

- Option previews showing the concrete rule each choice implies (the validation-coverage question rendered example claims with/without required citations) produced a one-round decision on the subtlest trade-off of the feature.

### Tools & Libraries

- Frontmatter model tiering made the "non-main-loop model" requirement literally free: Task-tool subagents run on their declared model, so `kb-architect`'s `model: sonnet` satisfied it with zero configuration — worth checking for native mechanisms before designing config surfaces.
