## Summary

The SDD Build phase now ends with a mandatory whole-branch adversarial review (sdd-build Step 5.5): the `code-reviewer` agent reviews the merge-base..HEAD diff with the feature's DEFINE acceptance tests as lens, Critical/Important findings enter a bounded fix loop (2 rounds), and the outcome is recorded as a contract-grade Review Verdict in the BUILD_REPORT. Ship refuses `dirty` and `missing` verdicts; autopilot enforces the same via the new Gate R. An opt-in `--tdd` flag adds RED-GREEN conduct per code task. Evidence base: the 2026-07-28 Superpowers-vs-AgentSpec benchmark, where AgentSpec shipped a UTC date bug behind a fully green suite — a bug class this gate demonstrably catches (proven blind during this run's acceptance tests).

## Lessons Learned

### Process

- Dogfooding the gate on its own implementation branch was the cheapest validation available: it surfaced 9 Important findings (stale docs, missing fallback, ambiguity) that static tests could not see. Make self-application standard for methodology features.
- The Design manifest missed `docs/getting-started/autopilot.md` — a doc invalidated by a contract change. Add a "which existing docs does this change invalidate?" check to sdd-design's manifest step.

### Technical

- Evidence partitioning matters for seeded-fault tests: the executor that plants a fault and then reviews it proves integration, not detection. Pair every seeded-fault run with a blind reviewer on a preserved artifact (here: the benchmark repo with the verified UTC bug).
- Three independent runs confirmed the tests-cannot-reach defect class is real and recurring: UTC date defaulting, unbounded-amount 500 (SQLite INTEGER overflow), and unhandled fetch errors — all behind green suites. The review gate targets exactly this class.

### Communication

- The Gate D pause on AT-002's execution mode prevented silently replacing the human's explicit interview choice with a cheaper test — and the resulting answer (B-then-A, fail-fast ordering) was better than either original option.

### Tools & Libraries

- Doc-contract pytest tests (asserting exact policy strings and cross-file numeric consistency) are a cheap drift alarm for markdown-encoded methodology — the budget-consistency test already guards the number most likely to drift.
