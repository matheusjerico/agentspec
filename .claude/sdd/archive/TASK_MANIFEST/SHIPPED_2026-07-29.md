## Summary

## Lessons Learned

### Process

- Adversarial probing of the FIX (not just the original findings) earns its cost: round 2's N1 — a false-positive class introduced by the round-1 fix — was caught only because the reviewer attacked the fix itself; both fix rounds of the budget were needed and sufficient.
- Cross-increment reviewer knowledge compounds: the Increment 2 heading-vocabulary lesson was applied at design time (presence parity from birth), and the review confirmed it held — the same Critical never recurred.

### Technical

- Section-locating by slug prefix is shadowable in both directions: a fence-less decoy hides the real section (false PASS), and a first-match-with-fence rule lets unrelated example fences hijack it (false FAIL). The sound rule: a candidate decides only when its fence actually declares the artifact's top-level key; syntactically broken fences stay fail-closed because their keys are uninspectable.
- Presence-vs-truthiness is not typing: a numeric `id: 42` passed the presence check while silently dropping out of every graph rule — boolean-ish and identity fields need explicit type checks (third YAML lesson of the program: quoted "off", quoted "false", now unquoted numerics).
- Excluding duplicated ids from graph analysis avoids misleading compound findings — one true finding beats two confusing ones.

### Communication

- Declaring the severity assignment as *documentation* in the contract YAML (with an explicit "editing this alone changes nothing" comment) prevents the false-configurability expectation the risk_profiles precedent created.

### Tools & Libraries

- Kahn's algorithm on `id → depends_on` adjacency is direction-agnostic for cycle detection — verified against self-loops and disconnected components; stdlib remains sufficient (no graph dependency added).
